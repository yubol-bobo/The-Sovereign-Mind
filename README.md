# The Sovereign Mind

**精神主权：AI 时代的终身阅读计划**

> 真正性感的大脑，不是储存了最多知识的大脑，
> 而是能在不同知识之间产生原创的连接，能理解复杂的人性，能欣赏微妙的美，
> 并且始终拥有自己独立判断的大脑。

**网站：<https://yubol-bobo.github.io/The-Sovereign-Mind/>** —— 一座可以转动的书房宇宙：161 本书绕着一颗发光的心智运行，跟着主线读、标记进度、推荐好书。

## 核心诉求

AI 可以替我检索、总结、分析，甚至模拟思考。但**拥有知识与经历知识，理解一个道理与形成自己的世界观，是完全不同的事。**

这个项目只守一件事：**精神主权**——我的注意力、判断、审美和人生答案，必须是我自己的。

它不是为了证明人比 AI 聪明，也不是为了变得博学或能引用更多名言。它是为了在一个认知越来越容易被外包的时代，仍然：

- 有**丰盈的内心**，而不是脑中空空；
- 有**自己的审美**，而不是被算法喂养的口味；
- 能**理解他人的痛苦**，而不是只会给人贴标签；
- 能在**没有标准答案的地方**，做出自己的选择。

方法是阅读——最"作弊"的方式：借用另一个人几十年的经验、痛苦、智慧和审美，重新认识自己与世界。

## 十一个方向

01–08 是向内和向上的：认识世界，安顿自己。09–11 是入世的：理解人心，处理金钱，动手做事。精神主权不是躲进书房，是带着自己的判断回到生活里。

| | 方向 | 核心问题 |
| --- | --- | --- |
| 01 | 认知主权 | 我的注意力、价值观和判断标准，有多少真正属于我自己？ |
| 02 | 自我与精神自由 | 如果不必满足任何人的期待，我会怎样度过这一生？ |
| 03 | 社会与人性洞察 | 我以为理所当然的世界，有多少是被社会建构出来的？ |
| 04 | 哲学与生命意义 | 如果效率、成就、财富都不能定义人生，什么能？ |
| 05 | 文学与情感深度 | 我是真的理解人，还是只会用几个概念解释人？ |
| 06 | 艺术与审美 | 我还能真正地看见、听见、感受世界，而不只是识别和消费它吗？ |
| 07 | 历史与文明视野 | 如果生在另一个时代、国家或阶层，我还会相信现在所信的吗？ |
| 08 | 科学与世界观 | 我追求的是真相，还是让我感觉正确的解释？ |
| 09 | 心理与内在世界 | 我的情绪、恐惧和重复犯的错，从哪里来？ |
| 10 | 财富与金钱观 | 多少才算够？我想用钱换什么？ |
| 11 | 创造与创业 | 我想让世界上多出一个什么东西？我愿意为它承担什么风险？ |

## 选书标准

每一本至少满足其中两条：

1. **思想密度** —— 读完之后，看世界多了一个再也摘不掉的镜头。
2. **审美密度** —— 句子本身值得慢读、重读、抄下来。
3. **生命密度** —— 一个真实或虚构的人，把一生摊开给你看。

不收：只有一个观点却写了三百页的畅销书、鸡汤、"X 分钟读懂 Y"。

另有一条贯穿始终的原则：**不因为喜欢一本书，就无条件相信它的全部观点。**

## 阅读纪律

1. **绝不让 AI 替我总结。** 困惑、停顿、反复回读，正是大脑在生长的过程，跳过它就什么都没发生。
2. **纸质书 + 一支笔。** 手机放在另一个房间。
3. **一本书，一页纸。** 用自己的话回答模板里的问题。写不出来，就是没读懂。
4. **只记"无用"的笔记。** 不做结构化摘要，只记让我心头一震、感到被冒犯、或想反驳作者的地方——那是我自己的思想在生长的位置。
5. **重读优于多读。** 不打卡，不统计字数，不追求数量。真正的好书，第二遍才开始。
6. **轻重交替。** 手边永远同时放一本思想类（训练理解世界的能力）和一本文学类（训练体验世界的能力）。
7. **允许弃读，但要写下为什么。**

## AI 在这个项目里的位置

思想陪练，不是阅读代理。

| 可以交给 AI | 必须留给自己 |
| --- | --- |
| 筛选值得读的书、整理计划 | 读原著 |
| 解释历史与文化背景 | 形成第一手理解 |
| 介绍不同学者的观点 | 判断自己是否认同 |
| 读完之后扮演反方，挑战我的理解 | 独立思考与辩论 |
| 提示跨学科的关联 | 产生真正属于自己的连接 |
| —— | 感受文学与艺术 |

## 节奏

- **每天 60 分钟**：40 分钟不被打断地读 → 10 分钟合上书，在脑中重构刚才读的 → 10 分钟用自己的话写下来。睡前另读半小时文学。
- **每周**：《红楼梦》两回，贯穿全年。
- **每月**：两本主线书。嫌多就一本——宁可慢，不可断。
- **每季**：回看笔记，挑一本重读。

## 网站

`书单.md` 是唯一的数据源。每次推送到 `main`，GitHub Actions 会运行 `scripts/build-data.mjs`（解析规则在 `scripts/booklist.mjs`）把它解析成 `site/data/books.json`，再把 `site/` 发布到 GitHub Pages。改书单只需要改 `书单.md`。

背后是一座赛博书房宇宙（`site/scene.js`，three.js r170）：161 本霓虹描边的书脊绕着发光的心智运行，下面是全息网格，数据流向中心汇聚，有辉光和镜头穿梭；往下滚动时，镜头依次飞向七颗恒星、主线内环、十一个星区，最后退回星海。帧率不够时会自动降低画质。

着色器写在 `site/scene-shaders.js`，`node scripts/check-shaders.mjs` 会用 glslangValidator（`apt install glslang-tools`）逐个编译。辉光等后期处理来自 three.js 官方 addons，放在 `site/vendor/postprocessing/` 和 `site/vendor/shaders/`，只把 `from 'three'` 改成了相对路径。

浏览器给不出 WebGL 2、或者第一帧画不出来时，首页会换成一排按季排列的书脊，其余功能不受影响；原因会打印在浏览器控制台，也写在 `<html data-scene-error>` 上。

### 改书名不会丢进度

读者的已读记录按书名（去掉《》和末尾括号里的说明）保存。只改括号里的说明不影响进度。如果真要给一本书改名，在 `scripts/booklist.mjs` 的 `RENAMED` 里写一行 `'新书名': ['旧书名']`，读者的记录会自动搬到新名字上。

### 提交前的检查

每个 PR 都会自动运行 `.github/workflows/check.yml`：书单能否解析、有没有重名或缺作者、有没有书从书单里消失（多半是改名忘了写 `RENAMED`）、网页脚本有没有语法错误、页面引用的本地文件是否都在、3D 着色器能否编译。本地也可以跑：

```bash
node scripts/check-booklist.mjs origin/main && node scripts/check-links.mjs && node scripts/check-shaders.mjs
```

分享链接时显示的预览图是 `site/og.png`，由 `python3 scripts/og-image.py` 生成（需要 Pillow 和一个中文字体）。

本地预览：

```bash
node scripts/build-data.mjs && python3 -m http.server -d site 8000
```

### 跨设备同步

已读记录默认只存在读者自己的浏览器里。点网站右上角的云图标，填一个只有 `gist` 权限的 GitHub token，记录就会保存到读者自己账号下的一个私密 Gist（`sovereign-mind-sync.json`），在每台设备上填同一个 token 即可看到同一份进度。两台设备的改动按每本书最新的一次标记合并。
